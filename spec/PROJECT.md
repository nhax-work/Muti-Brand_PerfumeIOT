## 1. What this project is

ScentStation is a platform where a customer picks a perfume on a kiosk screen, pays by QR code,
and receives exactly one spray. Each machine (`Machine`) holds several independently controlled
slots (`MachineSlot`) wired to a central admin platform that tracks transactions, remaining
perfume, device health, refills, and maintenance. The platform runs a **slot rental model**: the
platform owns and operates every machine; perfume brands (`Brand`) rent individual slots to
display their product. One machine can carry slots belonging to several different brands, and one
brand can rent multiple slots on the same machine and across different machines. Business data is
isolated at the slot level.

| Inside the system | External |
|---|---|
| Backend | Experience machine (`Machine`) — communicates over MQTT |
| Kiosk application | Payment gateway |

Rental model, from the platform's baseline business decisions:
- The platform owns and operates all machines, locations, and operations/technical/warehouse staff (BR-004, BR-011).
- A brand only manages its product catalog, its per-spray price on the slots it rents, its reports, and refill requests (BR-007, BR-011).
- One rental contract (`SlotRental`) covers exactly one slot; a brand renting 3 slots holds 3 independent contracts (BR-009).
- Pricing is free — no floor or ceiling (FR-SLT-08).
- Platform revenue = fixed periodic slot fee + revenue-share rate, configured per contract (BR-009).
- On contract expiry: paid grace period first, then liquidation to platform ownership if not renewed (BR-013) — see the `SlotRental` state machine in `spec/glossary.md`.

## 3. Mandatory rules

- **Contracts are frozen.** `erd.md`, `data-dictionary.md`, `schema.sql`, `openapi.yaml`, `mqtt.md`
  under `spec/contracts/` may not be edited directly once they exist. To change one: stop, write an
  ADR in `spec/decisions/` describing the problem and options, get it approved, then edit the
  contract and run `make test-contract` (`spec/contracts/README.md`).
- **Thresholds come from `spec/constraints.md` only.** Never hardcode a timeout, TTL, retry count,
  or rate limit — read the named constant (e.g. `DISPENSE_CMD_TTL_SEC`, `ORDER_PAYMENT_TTL_SEC`,
  `MACHINE_OFFLINE_SEC`) from configuration.
- **Error codes come from `spec/errors.md` only.** Agents must not invent new codes. A genuinely
  new case gets added to `errors.md` first (`SCREAMING_SNAKE_CASE`, no module prefix), then used.
- **Test naming:** `test_FR_<MODULE>_<số>_<mô_tả_ngắn>` (e.g. `test_FR_SLT_02_reject_occupied_slot`).
  `scripts/check_traceability.py` scans by this exact pattern; a misnamed test makes CI treat the
  FR as untested.
- **Data-scoping rule (BR-003, BR-012, FR-BND-05, FR-AUTH-07):** a brand user's queries must
  filter through `Order`/`SlotRental` brand ownership, never through `Machine` — `Machine` has no
  `brand_id`, because one machine hosts slots from multiple brands.

  ```sql
  -- CORRECT
  WHERE o.brand_id = :current_brand_id

  -- WRONG: this column does not exist
  WHERE m.brand_id = :current_brand_id
  ```

  A brand must never see another brand's identity, products, or existence on a shared machine
  (BR-012); unavailable slots belonging to other brands render as unavailable, with no further
  detail (FR-RPT-12).

## 5. Per-persona instructions

Personas below match the `agents` block in `harness.config.json` (also listed in `AGENTS.md` /
`CLAUDE.md`): Plan, Code, Review, Test, Doc, Security.

### 🗺️ Plan Agent
- Scope tasks along `FR-<MODULE>-<số>` boundaries and cite the BR each traces to (`docs/FR_NFR_SCENTSTATION.md`).
- Before planning work in `ORD`, `DSP`, `EXP`, `REV`, or any module other than `SLT`, check whether `spec/modules/<MODULE>.md` has real acceptance criteria yet — most don't; plan to write them rather than skip them.
- Never schedule a task that edits `spec/contracts/*` directly; schedule an ADR step first.
- When planning tests, plan their names as `test_FR_<MODULE>_<số>_<mô_tả_ngắn>` up front so traceability holds.

### 💻 Code Agent
- Enforce the data-scoping rule (Section 3) on every query touching brand-owned data — scope through `Order`/`SlotRental`, never `Machine`.
- Never hardcode a value covered by `spec/constraints.md`; read the named constant from config.
- Use only error codes already in `spec/errors.md`; if a new one is truly needed, add it there in a separate reviewed step before using it.
- Treat `order.brand_id`, `order.slot_rental_id`, `order.revenue_owner`, `order.price` as write-once at creation (`spec/contracts/README.md`, NFR-DAT-06) — no update path for these columns.
- Never edit files under `spec/contracts/` from a code change; that requires the ADR process in Section 3.

### 🔍 Review Agent
- Verify state transitions against `spec/glossary.md` exactly — e.g. `Order` only reaches `DISPENSED` after a device success result (FR-DSP-17), and a command in `UNKNOWN` must not trigger a new command (FR-DSP-19).
- Confirm the one-active-rental-per-slot and one-active-command-per-order invariants are enforced by a DB partial unique index, not just application code (FR-SLT-02, FR-DSP-05, NFR-DAT-07).
- Reject any PR whose brand-facing queries filter by `Machine` instead of `Order`/`SlotRental` brand ownership.
- Flag any PR that changes a file under `spec/contracts/` without a linked ADR in `spec/decisions/`.
- Require re-authentication checks on refund, inventory adjustment, diagnostic dispense, liquidation, and machine-config-change endpoints (FR-AUTH-09).

### 🧪 Test Agent
- Name every generated test exactly `test_FR_<MODULE>_<số>_<mô_tả_ngắn>`; `scripts/check_traceability.py` depends on this to count an FR as covered.
- Do not generate the 7 human-owned tests listed in Section 4 — leave them for a human and say so.
- Place tests in the right layer: `tests/unit/` (pure logic), `tests/integration/` (real DB, constraints, concurrency), `tests/contract/` (matches `openapi.yaml`/`mqtt.md`), `tests/e2e/` (full flow with the Device Simulator).
- Target ≥60% coverage on `ORD`, `DSP`, `SLT`, `EXP`, `REV`, `INV` — the CI coverage gate (`spec/testing.md`, NFR-MTN-01).

### 📝 Doc Agent
- When a module's FR is implemented, add its acceptance criteria to `spec/modules/<MODULE>.md` following the Given/When/Then format already used in `spec/modules/SLT.md` — don't leave the HTML-comment template in place.
- Cite BR/FR/NFR IDs only from `docs/FR_NFR_SCENTSTATION.md`; don't fabricate a code that isn't in that registry.
- Don't describe `spec/contracts/erd.md`, `schema.sql`, `openapi.yaml`, or `mqtt.md` as existing or final until they've actually been authored.
- Record every contract change as a new ADR in `spec/decisions/`, based on the `0001-mau.md` template.

### 🔒 Security Agent
- Check passwords are hashed with bcrypt or argon2 (NFR-SEC-03) and that no card or bank account data is ever persisted (NFR-DAT-04).
- Check every brand-scoped endpoint enforces slot-level isolation and returns `FORBIDDEN_SCOPE` on out-of-scope access (FR-AUTH-08, `spec/errors.md`).
- Check HTTPS/TLS 1.2+ for kiosk/backend/admin-web traffic and TLS for MQTT (NFR-SEC-01, NFR-SEC-02), and that each device has its own non-shared credentials (NFR-SEC-07, FR-MCH-02).
- Check `AuditLog` is append-only with no update/delete path, at the DB permission/trigger level (FR-AUD-09, NFR-SEC-08).
- Check no secret or credential is committed to source (NFR-SEC-05).

## 8. Git convention

Conventional Commits format (from `AGENTS.md` / `CLAUDE.md`): `feat:`, `fix:`, `refactor:`,
`test:`, `docs:`, `chore:`. Scope the commit to the module code where useful.

Worked example:

```
feat(SLT): enforce single active rental per slot (FR-SLT-02)

Add partial unique index uq_slot_active_rental on slot_rental(slot_id)
for status IN (ACTIVE, EXPIRING, GRACE, LIQUIDATED), per spec/contracts/README.md.
```
